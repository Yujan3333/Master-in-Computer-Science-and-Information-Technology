# Simple Key Exchange Protocol

## Definition

The **Simple Key Exchange Protocol** is the simplest protocol used to establish a **session key** between two users with the help of a **trusted Key Distribution Center (KDC)**.

The KDC generates a fresh **session key** and securely distributes it to both communicating parties.

It is called **simple** because it performs only **key distribution** and **does not provide mutual authentication**.

---

# Purpose

* To establish a temporary session key between two users.
* To enable secure communication using symmetric encryption.
* To reduce the need for sharing a permanent key between every pair of users.

---

# Entities Involved

* **Initiator A (Alice)**
* **Responder B (Bob)**
* **Key Distribution Center (KDC)**

---

# Symbols Used

| Symbol   | Meaning                                |
| -------- | -------------------------------------- |
| $A$      | Initiator (Alice)                      |
| $B$      | Responder (Bob)                        |
| $KDC$    | Key Distribution Center                |
| $K_A$    | Long-term key shared between A and KDC |
| $K_B$    | Long-term key shared between B and KDC |
| $K_S$    | Session key generated by the KDC       |
| $E(K,X)$ | Encrypt message $X$ using key $K$      |

---

# Protocol Steps

## Step 1: Initiator A → KDC

$$
\text{ID}_A \parallel \text{ID}_B
$$

**Explanation:**

A requests the KDC for a session key to communicate with B.

---

## Step 2: KDC → Initiator A

$$
E(K_A,,[K_S \parallel \text{ID}_B])
\parallel
E(K_B,,[K_S \parallel \text{ID}_A])
$$

**Explanation:**

The KDC:

* Generates a fresh session key $K_S$.
* Encrypts one copy using A's long-term key $K_A$.
* Creates another encrypted copy (ticket) for B using $K_B$.

A decrypts the first part to obtain the session key $K_S$.

---

## Step 3: Initiator A → Responder B

$$
E(K_B,,[K_S \parallel \text{ID}_A])
$$

**Explanation:**

A forwards B's encrypted ticket.

Since it is encrypted with $K_B$, only B can decrypt it.

B obtains the same session key $K_S$.

---

## Step 4: Secure Communication

Now both A and B possess the shared session key $K_S$.

They encrypt and decrypt all subsequent messages using $K_S$.

---

---

# Advantages

* Simple and easy to implement.
* Uses a fresh session key for each communication.
* Reduces the number of permanent shared keys.

---

# Disadvantages

* No mutual authentication.
* Vulnerable to replay attacks.
* Depends completely on the KDC.
* No freshness verification using nonces or timestamps.

---

# Comparison with Other Session Key Exchange Protocols

| Protocol                | Freshness Mechanism         | Authentication |
| ----------------------- | --------------------------- | -------------- |
| **Simple Key Exchange** | None                        | No             |
| **Needham–Schroeder**   | Nonces                      | Yes            |
| **Denning–Sacco**       | Timestamps                  | Yes            |
| **Otway–Rees**          | Session Identifier + Nonces | Yes            |
| **Kerberos**            | Tickets + Timestamps        | Yes            |

# 5-Mark Exam Answer

**Simple Key Exchange Protocol** is the most basic session key exchange protocol that uses a **Key Distribution Center (KDC)** to establish a shared session key between two users. The initiator requests a session key from the KDC. The KDC generates a fresh session key, encrypts it separately for the initiator and the responder using their respective long-term keys, and sends both encrypted messages to the initiator. The initiator forwards the responder's encrypted ticket, allowing both users to obtain the same session key for secure communication.

### Protocol

1.

$$
A \rightarrow KDC : \text{ID}_A \parallel \text{ID}_B
$$

2.

$$
KDC \rightarrow A :
E(K_A,,[K_S \parallel \text{ID}_B])
\parallel
E(K_B,,[K_S \parallel \text{ID}_A])
$$

3.

$$
A \rightarrow B :
E(K_B,,[K_S \parallel \text{ID}_A])
$$

4.

Both A and B use the shared session key $K_S$ for secure communication.

# **Limitations:**
The protocol does not provide mutual authentication or protection against replay attacks, which motivated the development of protocols such as Needham–Schroeder, Denning–Sacco, Otway–Rees, and Kerberos.
