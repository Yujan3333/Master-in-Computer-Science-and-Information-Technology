### 🔹 **What is SRS?**

An **SRS (Software Requirements Specification)** document clearly defines **what the software system must do**. It serves as an agreement between developers and clients.

---

### ✅ **Key Qualities of a Good SRS:**

|Quality|Description|
|---|---|
|**1. Correct**|The SRS must accurately describe the software’s functionality and constraints. Every requirement should be valid and verifiable.|
|**2. Unambiguous**|Each requirement should have **only one clear meaning**, avoiding confusion or misinterpretation.|
|**3. Complete**|All **functional and non-functional requirements**, diagrams, use cases, and assumptions should be included.|
|**4. Consistent**|No contradictions between different parts of the document. Requirements should not conflict.|
|**5. Verifiable**|Every requirement must be **testable** — you should be able to check whether it has been implemented correctly.|
|**6. Modifiable**|The document should be **structured and well-organized**, so changes can be made easily.|
|**7. Traceable**|Each requirement should be **uniquely numbered or labeled**, so it can be traced during development and testing.|
