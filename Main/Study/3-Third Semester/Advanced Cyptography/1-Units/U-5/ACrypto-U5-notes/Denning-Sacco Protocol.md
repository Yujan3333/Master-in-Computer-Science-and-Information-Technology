# Denning–Sacco Protocol

The **Denning–Sacco Protocol** is an improved version of the **Needham–Schroeder Symmetric Key Distribution Scheme (SKDS)**. It prevents **replay attacks** by including a **timestamp** in the ticket issued by the Key Distribution Center (KDC).

---

# Entities Involved

* **Initiator A**
* **Key Distribution Center (KDC)**
* **Responder B**

---

# Protocol Steps

## Step 1: Initiator A → KDC

$$
\text{ID}_A \parallel \text{ID}_B
$$

**Explanation:** Initiator $A$ requests the KDC to establish a session key for communication with responder $B$.

---

## Step 2: KDC → Initiator A

$$
E\left(K_a,,[K_s \parallel \text{ID}_B \parallel T]\right)
\parallel
E\left(K_b,,[K_s \parallel \text{ID}_A \parallel T]\right)
$$

Where:

* $K_a$ = Master key shared between A and KDC
* $K_b$ = Master key shared between B and KDC
* $K_s$ = Session key
* $T$ = Timestamp

**Explanation:** The KDC generates a fresh session key $K_s$ and timestamp $T$.

It sends:

* The session key encrypted with A's master key $K_a$.
* A **ticket** for B encrypted with B's master key $K_b$.

---

## Step 3: Initiator A → Responder B

$$
E\left(K_b,,[K_s \parallel \text{ID}_A \parallel T]\right)
$$

**Explanation:** A forwards the encrypted ticket to B.

---

## Step 4: Responder B

B decrypts the ticket using $K_b$ and obtains

$$
K_s,\ \text{ID}_A,\ T
$$

B then verifies the timestamp $T$.

* If the timestamp is valid, B accepts the session key $K_s$.
* If the timestamp has expired, B rejects the ticket.

---

## Step 5: Secure Communication

After successful verification, A and B use the shared session key $K_s$ for secure communication.

---

# Protocol Flow

```text
Initiator A                KDC                 Responder B
     |                      |                      |
     |---- IDA || IDB ----->|                      |
     |                      |                      |
     |<-- E(Ka,[Ks||IDB||T])||E(Kb,[Ks||IDA||T]) --|
     |                      |                      |
     |------ E(Kb,[Ks||IDA||T]) -----------------> |
     |                      |                      |
     |                 B decrypts ticket          |
     |                 Checks timestamp T         |
     |                      |                      |
     |<------ Secure communication using Ks ----->|
```

---

# How Denning–Sacco Prevents Replay Attack

### Needham–Schroeder Ticket

$$
E\left(K_b,,[K_s \parallel \text{ID}_A]\right)
$$

This ticket **does not contain a timestamp**. If an attacker records the ticket and later learns the old session key $K_s$, they can replay the ticket to B.

---

### Denning–Sacco Ticket

$$
E\left(K_b,,[K_s \parallel \text{ID}_A \parallel T]\right)
$$

Now the ticket contains the timestamp $T$.

Responder B checks whether $T$ is still valid.

* If $T$ is fresh, the ticket is accepted.
* If $T$ is old, the ticket is rejected.

Thus, replay attacks are prevented.

---

# Advantages

* Prevents replay attacks.
* Ensures the freshness of the session key.
* More secure than the Needham–Schroeder protocol.
* Uses timestamps instead of nonces for freshness verification.

---

# Disadvantages

* Requires synchronized clocks between users and the KDC.
* If clocks are not synchronized, valid tickets may be rejected.

# 5-Mark Exam Answer

**Denning–Sacco Protocol** is an improved version of the **Needham–Schroeder Symmetric Key Distribution Scheme**. It prevents replay attacks by including a **timestamp** in the ticket generated by the KDC. The KDC creates a fresh session key $K_s$ and timestamp $T$, encrypts the session key for A, and creates a ticket for B containing $K_s$, A's identity, and $T$. A forwards the ticket to B, who decrypts it and verifies the timestamp before accepting the session key. If the timestamp is valid, both A and B communicate securely using the session key.

### Protocol

1.

$$
A \rightarrow KDC : \text{ID}_A \parallel \text{ID}_B
$$

2.

$$
KDC \rightarrow A :
E\left(K_a,,[K_s \parallel \text{ID}_B \parallel T]\right)
\parallel
E\left(K_b,,[K_s \parallel \text{ID}_A \parallel T]\right)
$$

3.

$$
A \rightarrow B :
E\left(K_b,,[K_s \parallel \text{ID}_A \parallel T]\right)
$$

4.

$$
B \text{ decrypts the ticket and verifies } T.
$$

5.

$$
A \text{ and } B \text{ communicate securely using } K_s.
$$

**Key Difference:** Unlike the Needham–Schroeder protocol, Denning–Sacco includes the timestamp $T$ in the ticket, allowing B to detect and reject replayed (old) tickets, thereby preventing replay attacks.
