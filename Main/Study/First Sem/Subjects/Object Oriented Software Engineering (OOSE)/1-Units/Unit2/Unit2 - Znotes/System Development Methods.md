### SREM - Software Requirement Engineering Methodology

- A formal method for specifying software requirements
- Uses mathematical and logical techniques to precisely define what a system should do
- Focuses on creating detailed, unambiguous **requirements specifications**
- Emphasizes rigorous **documentation** and verification of requirement

---
### RDD - Responsibility Driven Design

- A design approach that starts with **detailed requirements** and drives the entire development process from those requirements
- The system architecture and design decisions are directly derived from the specified requirements
- *Functions* are designed to **meet specific requirements,** with data structures designed separately to support those functions

### SA - Structured Analysis

- A method for analyzing and understanding system requirements
- Uses tools like **Data Flow Diagrams (DFDs)** to show how data moves through the system
- Creates *process specifications that describe what each function does*!
- Separates the analysis of data flows from the analysis of data storage

### SD - Structured Design

- A method for designing system architecture based on **structured analysis**
- Uses **structure charts** to show the hierarchy of program modules/functions
- Emphasizes modular design with clear interfaces between functions
- Data structures are designed separately from the functional modules
