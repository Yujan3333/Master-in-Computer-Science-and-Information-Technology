| **Aspect**                  | **Function/Data Method (Procedural)**              | **Object-Oriented Method (OOP)**                      |
| --------------------------- | -------------------------------------------------- | ----------------------------------------------------- |
| 1. **Belongs To**           | Independent – not tied to any object               | Belongs to a class or object                          |
| 2. **Data Access**          | Accesses data via parameters                       | Accesses data through object attributes               |
| 3. **Encapsulation**        | No encapsulation – data and functions are separate | Follows encapsulation – data and methods are combined |
| 4. **Code Reusability**     | Limited reuse – reuse by copying functions         | High reuse – supports inheritance and polymorphism    |
| 5. **Modularity**           | Functional modularity                              | Class-based modularity                                |
| 6. **Security**             | Less secure – data is global or exposed            | More secure – data can be private/protected           |
| 7. **Ease of Maintenance**  | Harder to maintain as codebase grows               | Easier to maintain and extend                         |
| 8. **Function Call Style**  | `functionName(parameters)`                         | `objectName.methodName()`                             |
| 9. **Data Structure**       | Uses structures manually                           | Uses classes and objects                              |
| 10. **Real-world Modeling** | Poor at modeling real-world systems                | Excellent at modeling real-world entities (objects)   |
| 11. **Eg**                  | C , Pascal                                         | C++, Python , Java                                    |
