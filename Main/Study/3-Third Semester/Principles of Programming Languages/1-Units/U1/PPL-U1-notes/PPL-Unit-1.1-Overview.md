# Programming Languages Overview

## Why Study Programming Languages?

There are six main reasons to study programming languages:

1. **Improve Algorithm Development**
   Learning different approaches like recursion helps create efficient and elegant algorithms.

2. **Enhance Use of Current Languages**
   Understanding language implementation helps write faster and better code.

3. **Increase Vocabulary**
   Studying many languages gives more programming constructs and ideas.

4. **Better Language Choice**
   Helps choose the right language for the right task.

5. **Easier to Learn New Languages**
   Knowledge of concepts makes learning future languages faster.

6. **Easier to Design Languages**
   Existing language knowledge helps create new languages.

## History and Evolution of Programming Languages

Programming languages evolved with computer hardware.

### Timeline

* **1950s**

  * Early high-level languages introduced.
  * Examples: FORTRAN, LISP, FLOW-MATIC

* **1960s / 1970s**

  * Languages developed for large software systems.
  * Examples: Pascal, C, COBOL, Smalltalk

* **1980s / 1990s**

  * Rise of modern languages.
  * Examples: C++, Perl, Java

### Key Milestones

* **FORTRAN (1957)** → Scientific computing
* **COBOL (1960)** → Business applications
* **Simula 67** → Introduced OOP concepts
* **C (1972)** → Used to build UNIX

## Software Architectures and Their Impact

Programming environments influence language design.

### Mainframe Era

#### Batch Processing

* Processes jobs in groups.
* Timing less important.
* Errors costly.

#### Interactive Processing

* User communicates directly with system.
* Fast response needed.

### Personal Computer Era

* GUI, windows, graphics.
* Strong support for object-oriented programming.

### Embedded Systems

* Often no standard OS.
* Real-time response required.
* High reliability needed.

### Networking Era

* Distributed systems.
* Client-server computing.
* Web pages, email systems.

## Attributes of a Good Programming Language

### 1. Clarity and Simplicity

Easy to understand, write, and maintain.

### 2. Orthogonality

Features can combine freely without confusion.

### 3. Naturalness

Language structure matches problem domain.

### 4. Support for Abstraction

Use complex systems without knowing internal details.

### 5. Portability

Programs run on multiple systems.

### 6. Efficiency / Cost

Should minimize:

* Execution cost
* Compilation cost
* Maintenance cost

## Programming Paradigms

A **programming paradigm** is a style or way of solving problems.

---

### Imperative Paradigm

Focuses on **how** to solve the task through commands and statements.

#### Types

##### Procedural Programming

* Uses procedures/functions.
* Example: C

##### Object-Oriented Programming

* Uses classes and objects.

* Concepts:

  * Encapsulation
  * Inheritance
  * Polymorphism
  * Abstraction

* Examples: C++, Java, Python

---

### Declarative Paradigm

Focuses on **what** result is needed rather than how.

#### Types

##### Functional Programming

* Uses mathematical functions.
* Example: LISP

##### Logic Programming

* Based on facts and rules.
* Example: Prolog

---

## Language Standardization and Internationalization

### Standardization

Ensures same behavior across compilers.

#### Types

* **Proprietary Standard** → Owned by company
* **Consensus Standard** → Approved by groups like ANSI and ISO

### Internationalization

Supports global use:

* Unicode characters
* Different date/time formats
* Currency formats
* Multiple languages

---

## Programming Environments and Tools

A programming environment contains tools for software development.

### Common Tools

* Editor
* Compiler
* Debugger
* Verifier

### Separate Compilation

Large programs are divided into modules and compiled separately.

### Debugging Features

* **Execution Trace** → Track variable changes
* **Breakpoints** → Pause execution
* **Assertions** → Conditions that must remain true

### Job Control Language (JCL)

Used in mainframes to instruct OS how to process jobs.

Example tasks:

* Load files
* Run programs
* Manage outputs
