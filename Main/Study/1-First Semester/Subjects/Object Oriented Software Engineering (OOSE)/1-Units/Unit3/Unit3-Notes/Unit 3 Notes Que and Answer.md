### **i. What is requirement model? Explain with practical example. [2072]**

- A **requirement model** is a structured representation of what the system should do, based on user needs.
    
- It includes **functional** (what the system should do) and **non-functional** (performance, security, etc.) requirements.
    
- **Example**: In an online shopping app, requirements like "user can add items to cart" or "user must log in before checkout."
    

---

### **ii. Steps to develop the requirement model from user requirements [2074]**

1. **Gather user requirements** (interviews, surveys).
    
2. **Analyze** and **refine** the raw requirements.
    
3. **Model functional requirements** using use-case diagrams or scenarios.
    
4. **Model non-functional requirements** separately (like performance).
    
5. **Validate** the models with users.

### **iii. Model architecture vs. requirement model [2071]**

|Aspect|Model Architecture|Requirement Model|
|---|---|---|
|Purpose|Shows structure of system models|Shows what the system must do|
|Focus|How models relate to each other|What the system should deliver|
|Includes|Requirement, design, implementation models|Use-cases, user needs, constraints|

### **v. What is a component? Explain component management with example [2074]**

- A **component** is a reusable, independent software unit with defined interfaces.
    
- **Component management** involves selecting, integrating, updating, and maintaining those components.
    
- **Example**: A "chat" component in an app — managed by updating its version and ensuring it works with other parts.

### **vi. Construction Phase: Reasons and What’s Done [2071, 10 Marks]**

**Main Reasons:**

- To build a working product.
    
- To implement all design models in code.
    
- To prepare for testing and deployment.
    

**What is done:**

- Actual **coding** of system components.
    
- **Unit testing** and integration.
    
- Ensuring software meets design and requirements.
    
- **Documentation** of code.

### **viii. Classification of Real-Time System with Example [5 Marks, 2072]**

|Type|Description|Example|
|---|---|---|
|**Hard real-time**|Strict timing; failure = system failure|Airbag system|
|**Soft real-time**|Timing is important but not critical|Video streaming|
|**Firm real-time**|Deadline is important; late results discarded|Stock market updates|

### **ix. Requirement Engineering**

- It’s the process of **collecting, analyzing, documenting, and managing** software requirements.
    
- Includes: **Feasibility study**, **elicitation**, **analysis**, **specification**, **validation**, and **management**.
