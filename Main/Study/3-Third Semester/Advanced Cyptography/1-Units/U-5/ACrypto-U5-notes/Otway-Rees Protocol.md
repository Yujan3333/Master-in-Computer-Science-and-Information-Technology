# Otway–Rees Protocol

## Definition

The **Otway–Rees Protocol** is a **symmetric key authentication and key distribution protocol** that uses a **trusted Key Distribution Center (KDC)** to establish a **session key** between two users.

It was proposed by **Otway and Rees (1987)** to improve the **Needham–Schroeder protocol** by preventing **replay attacks** through the use of a **unique session identifier** and **nonces**.

---

# Purpose

* To establish a fresh session key between two users.
* To provide mutual authentication.
* To prevent replay attacks without relying on synchronized clocks (unlike Denning–Sacco).

---

# Entities Involved

* **Initiator A**
* **Responder B**
* **Key Distribution Center (KDC)**

---

# Symbols Used

| Symbol   | Meaning                                |
| -------- | -------------------------------------- |
| $A$      | Initiator (Alice)                      |
| $B$      | Responder (Bob)                        |
| $KDC$    | Key Distribution Center                |
| $K_A$    | Long-term key shared between A and KDC |
| $K_B$    | Long-term key shared between B and KDC |
| $K_S$    | Session key generated by KDC           |
| $N_A$    | Nonce generated by A                   |
| $N_B$    | Nonce generated by B                   |
| $M$      | Unique session identifier              |
| $E(K,X)$ | Encrypt message $X$ using key $K$      |

---

# Protocol Steps

## Step 1: Initiator A → Responder B

$$
M
\parallel
A
\parallel
B
\parallel
E(K_A,,[N_A \parallel M \parallel A \parallel B])
$$

**Explanation:**

A generates:

* Session identifier $M$
* Nonce $N_A$

A sends:

* Session identifier $M$
* Identity of A
* Identity of B
* An encrypted message containing $N_A$, $M$, $A$, and $B$

The encrypted part can only be read by the KDC because it is encrypted with $K_A$.

---

## Step 2: Responder B → KDC

$$
M
\parallel
A
\parallel
B
\parallel
E(K_A,,[N_A \parallel M \parallel A \parallel B])
\parallel
E(K_B,,[N_B \parallel M \parallel A \parallel B])
$$

**Explanation:**

B receives A's message.

B generates its own nonce $N_B$.

B adds another encrypted message using its long-term key $K_B$ and forwards everything to the KDC.

---

## Step 3: KDC → Responder B

The KDC decrypts both encrypted messages.

It verifies:

* Same session identifier $M$
* Correct identities
* Fresh nonces

Then it generates a session key $K_S$.

The KDC sends

$$
M
\parallel
E(K_A,,[K_S \parallel N_A])
\parallel
E(K_B,,[K_S \parallel N_B])
$$

**Explanation:**

The KDC creates:

* One message for A.
* One message for B.

Each message contains:

* Session key $K_S$
* The corresponding nonce

The nonces prove freshness.

---

## Step 4: Responder B → Initiator A

B decrypts

$$
E(K_B,,[K_S \parallel N_B])
$$

obtains the session key, and forwards

$$
M
\parallel
E(K_A,,[K_S \parallel N_A])
$$

to A.

A decrypts the message using $K_A$.

Since A receives its own nonce $N_A$, it knows the response is fresh and accepts the session key $K_S$.

Now both A and B share the same session key.

---

# Protocol Flow

```text id="v2swwi"
Initiator A               Responder B                 KDC
     |                         |                      |
     |---- M,A,B,EKA(...) ---->|                      |
     |                         |                      |
     |                         |---- Both messages -->|
     |                         |                      |
     |                         |<-- Session key ------|
     |                         |                      |
     |<--- EKA(KS,NA) ---------|                      |
     |                         |                      |
Secure communication using KS
```

---

# Why is the Session Identifier $M$ Used?

The session identifier $M$ uniquely identifies one execution of the protocol.

It prevents messages from different protocol runs from being mixed together.

---

# Why are Nonces Used?

* $N_A$ proves freshness to A.
* $N_B$ proves freshness to B.

The KDC returns each user's nonce along with the session key.

Each user verifies that the returned nonce matches the one they originally generated.

---

# Advantages

* Prevents replay attacks.
* Does not require synchronized clocks.
* Uses nonces to ensure freshness.
* Provides a fresh session key for every communication.

---

# Disadvantages

* Requires a trusted KDC.
* Involves more message exchanges than some other protocols.
* Communication cannot proceed if the KDC is unavailable.

---

# Comparison with Other Protocols

| Protocol          | Freshness Mechanism                                             |
| ----------------- | --------------------------------------------------------------- |
| Needham–Schroeder | Nonces (vulnerable to replay if old session key is compromised) |
| Denning–Sacco     | Timestamps                                                      |
| **Otway–Rees**    | Session identifier $M$ + Nonces                                 |

---

# 5-Mark Exam Answer

**Otway–Rees Protocol** is a symmetric key authentication and key distribution protocol that establishes a secure session key between two users through a trusted KDC. It uses a **unique session identifier ($M$)** and **nonces ($N_A$ and $N_B$)** to ensure message freshness and prevent replay attacks. The KDC verifies the requests, generates a session key $K_S$, and securely sends it to both users encrypted with their respective long-term keys. After decrypting the messages and verifying their nonces, both users share the same session key and communicate securely.
