# 1. Stream Cipher

A **stream cipher** is a symmetric encryption algorithm that encrypts plaintext **one bit or one byte at a time** rather than processing blocks of data.

It generates a **keystream**, which is combined with the plaintext using an operation such as **XOR**.

### Encryption

$$C_i = P_i \oplus K_i$$

### Decryption

$$P_i = C_i \oplus K_i$$

where

* $P_i$ = plaintext bit
* $C_i$ = ciphertext bit
* $K_i$ = keystream bit
* $\oplus$ = XOR operation

Because XOR is reversible, applying the same keystream again retrieves the plaintext.

### Characteristics of Stream Ciphers

* Encrypt data **bit-by-bit or byte-by-byte**
* Faster than block ciphers for continuous data
* Suitable for **real-time applications**

### Applications

* Wireless communication
* Mobile networks
* Streaming data encryption

---

## a. Synchronous Stream Cipher

A **synchronous stream cipher** generates the keystream **independently of the plaintext and ciphertext**.

Both sender and receiver must stay **synchronized** so they generate the same keystream.

### Operation

The keystream generator depends only on:

* secret key
* internal state

Encryption:

$$C_i = P_i \oplus K_i$$

Decryption:

$$P_i = C_i \oplus K_i$$

### Important Property

The keystream does **not depend on the ciphertext**.

### Advantages

* Simple design
* Fast encryption

### Disadvantages

* **Loss of synchronization causes decryption errors**
* If a bit is lost during transmission, all following bits may be incorrect.

---

## b. Asynchronous Stream Cipher

*(Self-Synchronizing Stream Cipher)*

An **asynchronous stream cipher** generates the keystream based on the **previous ciphertext bits**.

This means the cipher can **automatically resynchronize** if some bits are lost during transmission.

### Keystream generation

$$K_i = f(C_{i-1}, C_{i-2}, ..., C_{i-n})$$

where the keystream depends on previous ciphertext values.

Encryption:

$$C_i = P_i \oplus K_i$$

Decryption:

$$P_i = C_i \oplus K_i$$

### Advantages

* Automatically **resynchronizes after transmission errors**
* More robust in noisy communication channels

### Disadvantages

* More complex design
* Error propagation for several bits

# 4. Linear Feedback Shift Register (LFSR)

A **Linear Feedback Shift Register (LFSR)** is a shift register used to generate **pseudo-random sequences** for stream ciphers.

It consists of:

* a sequence of flip-flops (registers)
* feedback taps connected using **XOR operations**

The output bit is generated by **linearly combining selected register bits**.

---

## Structure of LFSR

If the register has $n$ stages:

$$s_{t+n}=c_1s_{t+n-1}\oplus c_2s_{t+n-2}\oplus ... \oplus c_ns_t$$

where

* $s$ = register bits
* $c_i$ = feedback coefficients
* XOR operation is used

---

## Example of LFSR

Consider a **4-bit LFSR** with feedback taps at positions **4 and 1**.

Initial state:

```
1 0 0 1
```

Feedback bit:

```
new bit = bit4 XOR bit1
```

### Step 1

```
Register: 1 0 0 1
Output: 1
Feedback: 1 XOR 1 = 0
Next state: 0 1 0 0
```

### Step 2

```
Register: 0 1 0 0
Output: 0
Feedback: 0 XOR 0 = 0
Next state: 0 0 1 0
```

This process continues to produce a **pseudo-random keystream**.

---

## Importance of LFSR

LFSRs are widely used in:

* stream cipher design
* pseudo-random number generation
* communication systems
* error detection systems

However, simple LFSRs alone are **not cryptographically secure**, so modern stream ciphers combine multiple LFSRs.

# 5. Autokey Cipher

The **Autokey Cipher** is a classical substitution cipher that improves the **Vigenère cipher** by using the plaintext itself as part of the key.

Instead of repeating the key, the cipher **appends plaintext to the key** to generate a longer key.

---

## Encryption Process

Key is extended using plaintext.

Example:

Plaintext:

```
ATTACKATDAWN
```

Initial key:

```
QUEENLY
```

Extended key:

```
QUEENLYATTACK
```

Encryption follows **Vigenère cipher rules**.

---

## Decryption Process

The receiver first uses the initial key, then gradually reconstructs the rest of the key from the decrypted plaintext.

---

## Advantages

* Key is **not repeated**, making frequency analysis harder.
* More secure than simple Vigenère cipher.

---

## Disadvantages

* If part of plaintext is guessed, the rest of the key can be recovered.
* Still vulnerable to modern cryptanalysis.
