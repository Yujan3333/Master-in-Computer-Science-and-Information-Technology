### Object-Oriented Software Engineering (OOSE)

- Object-Oriented Software Engineering (OOSE) is a software engineering **paradigm** that 
	- applies **object-oriented principles** throughout the *entire software development life cycle.* 

- It's an approach to building software systems that emphasizes the use of objects—which encapsulate **both data and behavior**—as fundamental building blocks.

---
### Objectory
 
 Objectory (Objectory Software Engineering) is a specific, comprehensive, and commercially available **process or methodology** for *Object-Oriented Software Engineering.*

- Think of OOSE as the broad field or discipline, and Objectory as a particular, well-defined way of _doing_ OOSE.
#### Key Characteristics of Objectory Process - Simplified

##### 1. **Structured Development Process**

- Provides a clear, step-by-step roadmap for building software
- Specifically designed for large, complex software projects
- Uses object-oriented techniques throughout

##### 2. **Use Case Driven**

- **Main Feature:** Everything revolves around "use cases"
- Use cases = How users will actually use the system
- Guides every step: requirements → analysis → design → testing
- Ensures the final product meets real user needs

##### 3. **Cost-Effective**

- Main goal: Reduce total cost of software over its lifetime
- Saves money on:
    - Initial development
    - Maintenance and updates
    - Future changes and improvements

##### 4. **Complete Coverage**

- Covers ALL stages of software development
- From initial idea → final working system
- Nothing is left out or skipped

##### 5. **Model-Based Approach**

- Uses different "models" (blueprints) at each stage:
    - **Requirements Model:** What the system should do
    - **Analysis Model:** How to organize the solution
    - **Design Model:** Technical details
    - **Implementation Model:** Actual code
    - **Test Model:** How to verify it works

##### 6. **Flexible and Adaptive**

- **Incremental:** Build the system piece by piece
- **Iterative:** Go back and improve earlier work
- Allows for continuous feedback and improvements
- Can adapt to changing requirements
