The **Prototyping Model** is a software development approach where a **prototype** (a working model or mock-up) of the software is built **before the actual system**.

This prototype helps users **visualize the system**, give **feedback**, and refine requirements.  
After multiple improvements, the final system is developed based on the prototype.
![](../../../../../../../../Attachments/Prototyping%20Model-fig-1.png)


### 🔄 Steps in Prototyping Model:

1. **Requirement Gathering**  
    – Collect initial requirements from the customer.
    
2. **Quick Design**  
    – Create a basic UI or flow of the system.
    
3. **Build Prototype**  
    – Develop a working model (limited features or mock-up).
    
4. **User Evaluation**  
    – User tests it and provides feedback.
    
5. **Refine Prototype**  
    – Update based on feedback; repeat until satisfied.
    
6. **Develop Final Product**  
    – Full system is built and delivered.
    

---

### 🧠 Example:

You're building a **food delivery app.**  
You first show a clickable prototype with login, menu, and cart features.  
Users suggest changes (like colors, button flow), then the final system is developed.

---

## ✅ Advantages:

- Users can **see the system early**
    
- Requirements become **clearer**
    
- Reduces **miscommunication**
    
- Helps identify **missing or incorrect features**
    

---

## ❌ Disadvantages:

- May cause **scope creep** (users keep asking for more)
    
- Too much focus on design, not system performance
    
- **Not suitable for large, complex systems**
    

---

### 📌 Summary Line:

> The Prototyping Model builds a working mock-up of the system early in development, allowing user feedback and refinement before final development.
