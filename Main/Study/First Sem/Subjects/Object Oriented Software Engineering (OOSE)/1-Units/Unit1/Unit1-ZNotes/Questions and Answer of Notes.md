### i. **Explain Object-Oriented Software Development with Example.**

**[10 Marks, 2071]**

**Definition:**  
Object-Oriented Software Development (OOSD) is the process of building software using the principles of object-oriented programming like **encapsulation, inheritance, and polymorphism**.

**Key Points:**

- Focuses on creating **objects** (real-world entities) and **classes**.
    
- Software is designed as a collection of interacting objects.
    
- Promotes **modularity**, **reusability**, and **maintainability**.
    

**Example:**  
Consider a **Library Management System**:

- Classes: `Book`, `Member`, `Librarian`, `Library`.
    
- `Book` class has attributes like `title`, `author`, and methods like `checkAvailability()`.
    
- Objects are created from these classes to perform actions like borrowing or returning a book.

### ii. **Explain Object-Oriented Development Process and Object-Oriented Analysis with Example.**

**[10 Marks, 2072]**

**Object-Oriented Development Process** includes the following stages:

1. **Object-Oriented Analysis (OOA)** – Understanding and modeling requirements using real-world objects.
    
2. **Object-Oriented Design (OOD)** – Creating class diagrams, interactions.
    
3. **Object-Oriented Programming (OOP)** – Actual implementation using languages like Java or C++.
    

**Object-Oriented Analysis (OOA):**

- Focuses on identifying the **objects** in the problem domain and their relationships.
    

**Example:**  
In an **Online Shopping System**:

- Objects: `Customer`, `Order`, `Product`, `Cart`.
    
- Relationships: A `Customer` places an `Order` that includes `Product(s)`.

### iii. **What is Requirement Model? Explain with Practical Example.**

**[2072]**

**Definition:**  
A **requirement model** describes **what the system should do** — both **functional** and **non-functional requirements** — and helps developers understand the customer's needs.

**Components:**

- Use-case diagrams
    
- Class diagrams
    
- Requirement specifications
    

**Example:**  
In a **Banking System**:

- Functional requirement: User can **check balance** and **transfer money**.
    
- Non-functional: The system must respond within **2 seconds**.
    
- Use-case: "Transfer Money" showing actor (user) and system interaction.

### iv. **Differentiate Between Model Architecture and Requirement Model.**

**[2071]**

|**Aspect**|**Model Architecture**|**Requirement Model**|
|---|---|---|
|**Purpose**|Structure of the system and components|Captures what the system should do|
|**Focus**|Layers/modules and their interactions|User needs, use-cases, and system functions|
|**Used For**|Design and planning|Analysis and understanding of requirements|
|**Includes**|Components, layers, subsystems|Functional and non-functional requirements|
|**Example**|3-tier architecture (UI, Logic, DB)|Use-case diagram showing "Login", "Withdraw", etc.|

### v. **Explain with Example Software Process Model and Software Process.**

**[10 Marks, 2075]**

**Software Process:**  
A **software process** is a set of activities for developing software — like **requirement gathering**, **design**, **coding**, **testing**, and **maintenance**.

**Software Process Model:**  
It is a **framework** or **approach** that organizes these activities in a structured way.

**Examples of Process Models:**

- **Waterfall Model** – linear, phase-by-phase.
    
- **Spiral Model** – iterative with risk analysis.
    
- **Agile Model** – fast, flexible, iterative delivery.
    
- **Prototyping** – quick model for feedback.
    

**Example:**  
In a **Hospital System**, the team may use **Spiral Model** to first build a risk-free appointment system, then expand to billing and records.

### vi. **Differentiate Between Object-Oriented Software Engineering and Object-Oriented Software Development.**

**[10 Marks, 2074]**

|**Aspect**|**OOSE**|**OOSD**|
|---|---|---|
|**Scope**|Complete project life cycle|Mainly implementation (coding)|
|**Focus**|Requirements, analysis, design, quality, testing|Class creation, object interaction, programming|
|**Who Uses It**|Engineers, architects|Developers, coders|
|**Includes**|Planning, UML, models, testing, tools|Writing code using OO languages|
|**Example**|Designing the whole **school system** architecture|Writing the `Student` and `Teacher` classes in code|

### vii. **Explain Object-Oriented System Design and Object-Oriented Program Design with Example.**

**[10 Marks, 2074]**

|**Aspect**|**Object-Oriented System Design (OOSyD)**|**Object-Oriented Program Design (OOPD)**|
|---|---|---|
|**Focus**|Designing the system architecture and interactions|Designing class structures and methods|
|**Scope**|Broader – deals with modules, interfaces, subsystems|Narrower – focuses on coding logic and algorithms|
|**Includes**|Use-case diagrams, class diagrams, sequence diagrams|Method definitions, control flows, class structure|
|**Goal**|Build a complete, scalable system design|Write detailed code-level logic|
|**Example**|Designing how `Customer`, `Cart`, `Order` interact|Writing the `addToCart()` method for the `Cart` class|
