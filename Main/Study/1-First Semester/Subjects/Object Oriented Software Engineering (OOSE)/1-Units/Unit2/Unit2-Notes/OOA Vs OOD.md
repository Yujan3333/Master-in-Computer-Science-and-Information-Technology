

|Aspect|**OOA (Object-Oriented Analysis)**|**OOD (Object-Oriented Design)**|
|---|---|---|
|**Definition**|Analyzing and modeling the **problem domain** using object-oriented concepts.|Designing a **solution** to the problem using OO principles.|
|**Focus**|**What** the system must do (functional requirements).|**How** the system will do it (implementation details).|
|**Goal**|Understand the real-world problem and user requirements.|Create a blueprint for the software system.|
|**Output**|Analysis model (use cases, class diagrams, etc.).|Design model (class structure, interfaces, subsystems, architecture).|
|**Activities**|- Identifying actors and use cases- Finding entities and relationships|- Refining classes- Defining methods and data structures- Mapping to code|
|**Abstraction Level**|High-level, conceptual view|Mid- to low-level, closer to implementation|
|**Tools/Diagrams Used**|Use Case Diagrams, Class Diagrams (conceptual), Sequence Diagrams|Class Diagrams (detailed), Component Diagrams, Deployment Diagrams|
|**Example Output**|- "Customer places an order"- Class `Customer`, `Order` identified|- Class `Customer` has method `placeOrder()`- Database schema defined|
